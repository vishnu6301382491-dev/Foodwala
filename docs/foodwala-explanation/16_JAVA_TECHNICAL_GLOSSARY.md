# 16. Master Technical Glossary: 100+ Full-Stack Engineering Terms

A definitive glossary of 100+ essential full-stack Java, Spring, database, security, and cloud terms. Each definition includes a simple English explanation and an exact FoodWala implementation reference.

---

### Core Java & JVM Internals (1 - 25)

1. **JVM (Java Virtual Machine)**: The abstract runtime engine that translates compiled bytecode into machine code for the host OS. *FoodWala: Executes all Servlets and DAOs on Tomcat.*
2. **JRE (Java Runtime Environment)**: Software bundle containing the JVM plus standard Java core libraries.
3. **JDK (Java Development Kit)**: Complete developer kit containing compiler (`javac`), runtime (`JRE`), and debugging tools.
4. **Bytecode**: Platform-independent intermediate code (`.class` files) generated by `javac`.
5. **Garbage Collection (GC)**: Automatic memory manager in the JVM that destroys unreachable objects from the heap to prevent memory leaks.
6. **Heap Memory**: Memory region where all Java objects and instance variables are allocated.
7. **Stack Memory**: Memory region where local method variables and execution call frames reside.
8. **Class**: A blueprint defining attributes and behaviors. *FoodWala: `Restaurant.java` defines the restaurant blueprint.*
9. **Object**: A concrete instance of a class occupying heap memory. *FoodWala: `Restaurant empire = new Restaurant();`.*
10. **Constructor**: Special method called when an object is instantiated. *FoodWala: `CartItem(int itemId, String name, double price, int qty)`.*
11. **Encapsulation**: Hiding internal state by making variables `private` and exposing `public` getters/setters. *FoodWala: `User.java`.*
12. **Inheritance**: Deriving fields and methods from a parent class via `extends`. *FoodWala: `CheckoutController extends HttpServlet`.*
13. **Polymorphism**: The ability of an object to take multiple forms through method overloading or overriding.
14. **Method Overloading**: Defining methods with the same name but different argument lists in the same class. *FoodWala: `SMSService.sendSMS()`.*
15. **Method Overriding**: Subclass re-defining a parent method with the exact same signature. *FoodWala: `@Override protected void doGet(...)`.*
16. **Interface**: A formal contract of abstract methods. *FoodWala: `UserDAO.java` defines CRUD operations.*
17. **Abstract Class**: A class that cannot be instantiated on its own and may contain both abstract and concrete methods. *FoodWala: `HttpServlet`.*
18. **Static**: Keyword indicating that a member belongs to the class type itself rather than object instances. *FoodWala: `DBConnection.getConnection()`.*
19. **Final**: Keyword making a variable constant, a method non-overridable, or a class non-inheritable. *FoodWala: `public final class PasswordUtil`.*
20. **Immutable**: An object whose state cannot be altered after creation. *FoodWala: Java `String`.*
21. **Pass-by-Value**: Java always passes copies of primitives or copies of object reference pointers into methods.
22. **Exception**: An event disrupting normal program flow. *FoodWala: `SQLException` caught during database operations.*
23. **Checked Exception**: Exceptions checked at compile-time (e.g. `IOException`, `SQLException`).
24. **Unchecked Exception**: Runtime exceptions that don't require mandatory `try-catch` (e.g. `NullPointerException`, `IllegalArgumentException`).
25. **Try-with-Resources**: Java 7 construct that automatically closes `AutoCloseable` resources (like `Connection` and `PreparedStatement`) without manual `finally` blocks.

### Java Collections & Generics (26 - 35)

26. **Collections Framework**: Standardized architecture for storing and manipulating groups of objects.
27. **List**: Ordered collection allowing duplicates. *FoodWala: `List<Restaurant>`.*
28. **ArrayList**: Resizable-array implementation of `List` offering $O(1)$ fast random index access.
29. **Set**: Unordered collection containing no duplicates. *FoodWala: `Set<String> cuisines` in `RestaurantApiController`.*
30. **HashSet**: Hash-table backed `Set` providing $O(1)$ lookup and insertion.
31. **Map**: Key-value data structure where keys are strictly unique. *FoodWala: `Map<Integer, CartItem>` in `Cart.java`.*
32. **HashMap**: Hash-table based `Map` calculating key bucket locations via `hashCode()`.
33. **Generics**: Type parameterization allowing classes and methods to operate on specified object types safely at compile-time (`List<Restaurant>`).
34. **Lambda Expression**: Anonymous inline function passing behavior as data: `items.forEach(item -> total += item.getPrice())`.
35. **Stream API**: Functional pipeline sequence supporting filter, map, and reduce operations on collections.

### Spring Framework & Spring Boot (36 - 55)

36. **Inversion of Control (IoC)**: Architectural pattern shifting object creation from application code to a container.
37. **Dependency Injection (DI)**: Passing dependent objects into a class via constructor or setter rather than creating them with `new`.
38. **Spring Bean**: Any Java object instantiated and managed by the Spring IoC container.
39. **ApplicationContext**: The central interface representing the Spring IoC runtime container.
40. **DispatcherServlet**: The front-controller servlet that intercepts all incoming web requests in Spring MVC.
41. **Auto-Configuration**: Spring Boot mechanism that automatically configures beans based on classpath dependencies.
42. **`@SpringBootApplication`**: Composite annotation enabling `@Configuration`, `@EnableAutoConfiguration`, and `@ComponentScan`.
43. **`@Component`**: Generic stereotype marking a Java class as a Spring-managed bean.
44. **`@Service`**: Stereotype designating business logic classes in the service tier.
45. **`@Repository`**: Stereotype designating database access classes; translates low-level database exceptions.
46. **`@Controller`**: Stereotype designating Spring MVC web controllers returning view names.
47. **`@RestController`**: Specialized controller combining `@Controller` and `@ResponseBody` for JSON REST APIs.
48. **`@Autowired`**: Injects matching Spring bean dependencies automatically.
49. **`@Configuration`**: Marks a class containing bean definitions via `@Bean` methods.
50. **`@Bean`**: Method-level annotation registering the returned object as a Spring bean.
51. **`@Value`**: Injects configuration properties from `application.properties` into Java fields.
52. **`@PathVariable`**: Extracts dynamic URL template variables (`/api/orders/{id}`).
53. **`@RequestParam`**: Extracts query parameters (`/api/search?q=biryani`).
54. **`@RequestBody`**: Deserializes the JSON HTTP body into a Java DTO.
55. **`@Transactional`**: Manages atomic database transactions with automatic commit and rollback.

### Database, ORM & JPA (56 - 70)

56. **RDBMS**: Relational Database Management System storing data in tables of rows and columns. *FoodWala: MySQL.*
57. **JDBC (Java Database Connectivity)**: Standard Java API for connecting and executing SQL against databases.
58. **`PreparedStatement`**: Pre-compiled SQL statement with parameterized `?` placeholders preventing SQL injection.
59. **Connection Pool**: Cache of reusable database connections reducing connection handshake overhead.
60. **Normalization**: Organizing relational tables into 1NF, 2NF, 3NF to eliminate redundant data.
61. **ACID Properties**: Atomicity, Consistency, Isolation, Durability—guarantees of relational transactions.
62. **Primary Key**: Unique identifier column for each row in a table. *FoodWala: `order_id`.*
63. **Foreign Key**: Column referencing a primary key in another table enforcing referential integrity. *FoodWala: `orders.user_id`.*
64. **JPA (Jakarta Persistence API)**: Java specification defining object-relational mapping.
65. **Hibernate**: Popular ORM framework that implements the JPA specification.
66. **`@Entity`**: JPA annotation marking a Java class as a persistent database entity.
67. **`@Table`**: Specifies the database table mapped by a JPA entity.
68. **`@ManyToOne`**: JPA relationship mapping where multiple entities reference one parent. *FoodWala: Many Orders belong to One User.*
69. **`@OneToMany`**: JPA relationship mapping where one entity owns a collection of children. *FoodWala: One Order has Many OrderItems.*
70. **Lazy Loading**: Delaying the database fetch of child entities until they are explicitly accessed in code.

### Web Architecture & REST APIs (71 - 85)

71. **Servlet**: Server-side Java class handling HTTP requests and generating responses. *FoodWala: `CartController`.*
72. **Tomcat**: Open-source web server and Java Servlet/JSP container.
73. **JSP (JavaServer Pages)**: Template engine compiling HTML and Java code into servlets.
74. **REST (Representational State Transfer)**: Architectural style for stateless network web services.
75. **HTTP GET**: Idempotent request retrieving data without modifying server state.
76. **HTTP POST**: Non-idempotent request submitting data to create a new resource.
77. **HTTP PUT**: Idempotent request completely replacing an existing resource.
78. **HTTP DELETE**: Idempotent request deleting a resource.
79. **Idempotence**: A property where executing an operation multiple times leaves the system in the exact same state as executing it once.
80. **JSON**: Lightweight, text-based data interchange format (`application/json`).
81. **DTO (Data Transfer Object)**: Pattern decoupling database models from external API contracts.
82. **Serialization**: Converting a Java object into a byte/text format (e.g. JSON string).
83. **Deserialization**: Reconstructing a Java object from a JSON string.
84. **`response.sendRedirect()`**: Server sends an HTTP 302 instructing the browser to make a new GET request.
85. **`RequestDispatcher.forward()`**: Server internally forwards the request to another resource without changing the browser URL.

### Security, Cryptography & Integrations (86 - 105)

86. **Authentication**: Verifying *who* the user is (e.g. email and password verification).
87. **Authorization**: Verifying *what* the authenticated user is allowed to do (RBAC roles).
88. **Argon2id**: Memory-hard cryptographic password hashing algorithm recommended by OWASP. *FoodWala: `PasswordUtil.java`.*
89. **BCrypt**: Adaptive password hashing function utilizing salt rounds and the Blowfish cipher.
90. **Salt**: Cryptographically random bytes added to passwords before hashing to defeat precomputed rainbow tables.
91. **HMAC-SHA256**: Keyed-Hash Message Authentication Code ensuring data integrity. *FoodWala: Razorpay signature check.*
92. **Session**: Server-side state store tied to a client via an HTTP-only cookie (`JSESSIONID`).
93. **Cookie**: Small key-value data stored by the browser and transmitted on every HTTP request.
94. **JWT (JSON Web Token)**: Compact, URL-safe stateless token containing signed claims (`header.payload.signature`).
95. **SQL Injection**: Cyberattack where malicious SQL is injected into queries; defeated 100% by `PreparedStatement`.
96. **CORS (Cross-Origin Resource Sharing)**: HTTP header mechanism allowing servers to specify which external domains can load resources. *FoodWala: `CORSFilter.java`.*
97. **XSS (Cross-Site Scripting)**: Vulnerability allowing attackers to inject malicious client-side scripts into web pages.
98. **CSRF (Cross-Site Request Forgery)**: Attack forcing authenticated users to submit unwanted actions on a trusted web application.
99. **Razorpay**: Cloud payment aggregator enabling UPI, card, and net-banking payments.
100. **Haversine Formula**: Mathematical equation computing great-circle spherical distance between GPS coordinates. *FoodWala: `LocationUtil.java`.*
101. **Leaflet.js**: Open-source JavaScript interactive map engine for rendering live valet coordinates.
102. **Cloudflare Tunnel**: Zero-trust edge daemon (`cloudflared`) exposing local ports over encrypted HTTPS tunnels.
103. **Webhook**: HTTP POST callback mechanism allowing one system to notify another in real-time when an event occurs. *FoodWala: Meta WhatsApp events.*
104. **Git**: Distributed version control system tracking source code revisions.
105. **GitHub Pages**: Static edge CDN hosting HTML, CSS, JavaScript, and client assets.
